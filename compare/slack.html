Moving from Slack's own export to SlackVault

Slack is the chat itself. Its paid plans keep unlimited history inside Slack, searchable where people already work, and if your team can pay per user, that is the simplest answer with nothing extra to run.

SlackVault is for a team staying on the free plan for now. It copies messages and threads into your own Firebase project every 15 minutes while a browser with the extension is running. You don't leave Slack for this, and nobody on the team changes how they work.

The steps​

  1. Sync soon, because the window moves. SlackVault can copy only what Slack's API still returns for your plan, and anything that slides out before a sync saves it is out of reach. Create the Slack app, your Firebase project (Firebase setup) and the browser extension, then run the first sync as Syncing & your archive describes.
  2. Load an export if a workspace owner or admin has one from Slack. Merge it into one file first:

SlackVault's Import page reads one JSON file, not a ZIP, so a Slack export needs merging first. Unzip it and run this inside the folder that holds users.json and channels.json, with jq installed:

jq -n --slurpfile users users.json --slurpfile channels channels.json \
  --slurpfile msgs <(for c in $(jq -r '.[] | "\(.id):\(.name)"' channels.json); do
    jq -s --arg id "${c%%:*}" '{($id): add}' "${c#*:}"/*.json
  done) \
  '{users: $users[0], channels: $channels[0], messages: ($msgs | add)}' > slackvault-import.json

Then upload slackvault-import.json on the Import page of the web app, as described in Search & export. Merge mode adds new records and updates existing ones. Private channels and DMs need their own export files, which this command doesn't cover.

  1. Know what happens if you upgrade later. There is no way yet to send records back into Slack. The history in your Firebase project stays there and doesn't flow back.

Last checked November 7, 2026. Check Slack (own plans and export) for yourself. SlackVault is not affiliated with or endorsed by Slack.

What SlackVault does not do

  • Messages, channels, members and file records go to your own Firebase project. Supabase is not supported yet.
  • Files do not go to your Google Drive or your Firebase project. When file copying is switched on in our extension build, each file uploads to our file storage with its visibility set to public: the link is hard to guess, but anyone holding it can open the file without signing in. Where no storage key is set in the build, no copy is made, and your archive keeps the file’s details and Slack’s link, which works only while Slack serves that file.
  • There is no way yet to send records back into Slack.
  • The sync runs in a browser extension, every 15 minutes, only while that browser is running.
  • SlackVault can copy only what Slack’s API still returns, so anything older than your plan’s window is out of reach unless an earlier sync already saved it.
  • If saving one thread fails, the sync logs it and moves on without retrying those replies.
  • Search checks the most recent page of messages, up to 50 per query, not the whole archive.
  • The extension and the Android app have no store listing yet, and the source code is in a private repository.
